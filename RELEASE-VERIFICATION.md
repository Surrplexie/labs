## Step-by-step verification

### Windows

```powershell
# 1. Compute the hash of the file you downloaded
(Get-FileHash .\workflow_gui.exe -Algorithm SHA256).Hash.ToUpper()

# 2. Open SHA256SUMS.txt and read the expected hash
Get-Content .\SHA256SUMS.txt

# 3. Compare the two values manually -- they must be identical.
#    A single character difference means the file has been altered.
```

One-liner that compares automatically and prints PASS or FAIL:

```powershell
$expected = ((Get-Content .\SHA256SUMS.txt | Where-Object { $_ -match 'workflow_gui.exe' }) -split '\s+')[0].ToUpper()
$actual   = (Get-FileHash .\workflow_gui.exe -Algorithm SHA256).Hash.ToUpper()
if ($actual -eq $expected) { Write-Host "PASS -- hashes match" -ForegroundColor Green }
else { Write-Host "FAIL -- hashes do NOT match`n  expected: $expected`n  actual:   $actual" -ForegroundColor Red }
```

### Linux / macOS

```bash
# 1. Compute hash
sha256sum workflow_gui

# 2. Read expected value
cat SHA256SUMS.txt

# 3. Or let sha256sum verify automatically (-c flag):
sha256sum -c SHA256SUMS.txt
# Prints: workflow_gui: OK   (or FAILED)
```

## Reading the SHA256SUMS.txt file

The file produced by CI looks like this:

```
# SHA256SUMS -- workflow_gui Windows build
# Generated  : 2026-05-11T15:00:00Z
# Python     : Python 3.12.x
# PyInstaller: 6.20.0
# Source hash: <SHA256 of workflow_gui.py at build time>  workflow_gui.py

<SHA256 of the .exe>  workflow_gui.exe
```

The `Source hash` line lets you verify that the `.py` source that produced
this binary matches the source in the repository at the same tag:

```powershell
# On Windows -- compare source hash in SHA256SUMS.txt to the .py in your clone
(Get-FileHash .\30_scripts\workflow_gui.py -Algorithm SHA256).Hash.ToUpper()
```

```bash
# On Linux
sha256sum 30_scripts/workflow_gui.py | tr 'a-f' 'A-F'
```

## Reading the SBOM (sbom.cdx.json)

The SBOM is a CycloneDX JSON listing every Python package present in the build
environment.  You do not need to act on it to use the binary; it is provided
for auditing purposes.

To view the component list:

```bash
python -m json.tool sbom.cdx.json | grep '"name"'
```

Or open it in any CycloneDX-compatible viewer (e.g. OWASP Dependency-Track).

The expected runtime dependency tree for `workflow_gui` is intentionally
minimal: only PyInstaller and the Python standard library are used.  Any
unexpected packages in the SBOM should be treated as noteworthy.

## Reproducing the build yourself

If you do not want to trust the release binary, build it locally from source:

```powershell
# Windows -- requires Python 3.10+ on PATH
git clone https://github.com/<your-user>/labs.git
cd labs
powershell -ExecutionPolicy Bypass -File .\30_scripts\build_exe.ps1
# Output: dist\workflow_gui.exe + dist\SHA256SUMS.txt
```

```bash
# Linux -- requires Python 3.10+ with tkinter
git clone https://github.com/<your-user>/labs.git
cd labs
bash ./30_scripts/build_linux.sh
# Output: dist/workflow_gui + dist/SHA256SUMS.txt
```

The build scripts install the exact PyInstaller version pinned in
[`30_scripts/build_requirements.txt`](./30_scripts/build_requirements.txt).
Local builds will produce a functionally equivalent binary but a different
SHA-256 (platform, Python patch version, and OS ABI differences are expected).
